# 覆盤作業手冊（Playbook）

> 呢份文件係「點做覆盤」嘅唯一標準。每次覆盤都跟同一套流程、同一套門檻、同一個格式，
> 所以隔幾個月翻查都比較得到。想改規則，就改呢份文件 + `tools/metrics.py`，並喺覆盤記錄寫明「規則修訂」。

## 1. 目的

- 把「當時點諗」同「後來發生咩」分開記錄，事後可以覆核，唔可以事後孔明。
- 每次只用**可量化**嘅價量數據講嘢：價位、均線、廣度、派貨日、成交。
- 輸出要令朋友睇得明，但唔可以變成投資建議。

## 2. 節奏

| 情況 | 做法 |
|---|---|
| 每個交易日收市後 | 跑 `tools/review.py`，得到快照（`data/`）同草稿（`drafts/`） |
| 一週一次（建議週末） | 寫成正式覆盤，貼入 `stan-weinstein-review-log.md` |
| 有大事（爆邊、FTD、聯儲局、大型業績） | 即日加一節，標明「特別覆盤」 |
| 舊判斷被推翻 | **唔改舊文**，開新一節寫「修訂」，講明邊條判斷錯、點解 |

## 3. 一次覆盤嘅四個步驟

```bash
# ① 抓數 + 計指標 + 畫圖 + 出草稿（一次過）
python3 tools/review.py

# ② 睇草稿，補判讀
open drafts/2026-11-24.md

# ③ 貼入覆盤記錄（新增一節，唔改舊節）
# ④ 發佈
git add -A && git commit -m "review 2026-11-24" && git push
```

程式會自動做嘅事：

1. 抓 33 隻 ETF + 43 隻美股嘅日線（Nasdaq API，有本地 cache，唔會重複抓）。
2. 計：20/50/150/200 日線、斜率、RSI(14)、ATR、52 週高低、成交比、Stage 分類。
3. 計：市場廣度（高於 20 日線比例、20 日新高／新低）、派貨日、FTD 狀態、缺口。
4. 存快照 `data/YYYY-MM-DD.json`（歷史永久保留，用嚟同上次比較）。
5. 畫三張 SVG：`assets/img/YYYY-MM-DD/{indices,breadth,sectors}.svg`。
6. 出草稿 `drafts/YYYY-MM-DD.md`，數字全部填好，只剩「判讀」同「結論」要人手寫。

## 4. 固定門檻（唔可以每次改）

| 指標 | 定義 | 門檻／用法 |
|---|---|---|
| Stage 2 | 價 > 150 及 200 日線、50 > 200、200 日線向上 | 可持有／搵入場 |
| Stage 3 | 價 > 200 日線但 200 日線轉平／向下 | 減倉、收緊止蝕 |
| Stage 4 | 價 < 150 及 200 日線、200 日線向下 | 唔好買，等 Stage 1 |
| 派貨日 | 跌 > 0.2% 且成交高過前一日 | 25 個交易日內 ≥ 5 個要小心 |
| FTD | 由近期低位起第 4 日或之後，單日升 ≥ 1.5%、成交放大、收上半部 | 出現才算「反彈確認」 |
| 廣度推力 | 高於 20 日線嘅股票比例 | ≥ 60% 才算牛市中嘅健康推力 |
| 廣度極端 | 同一比例 | < 20% 屬超賣區，但唔等於見底 |
| 缺口 | 當日開市 vs 上日高位 | 即日補 = 弱；幾日唔補 = 強 |
| 信貸 | HYG、LQD 對 200 日線 | 股市升但信貸唔跟 = 反彈質素差 |
| 美元 | UUP 對 200 日線 + RSI | 強美元 = 新興市場／商品壓力 |

## 5. 報告結構（固定 9 節）

1. **一頁摘要** — 3–5 條 bullet，每條最少一個數字。
2. **指數與 Stage** — SPY／QQQ／IWM 為主，講收復定失守邊條均線。
3. **市場廣度** — 高於 20 日線比例、新高／新低家數。
4. **派貨日與 FTD** — 呢兩項決定「反彈係咪可信」。
5. **板塊輪動** — 邊個板塊領先、邊個落後（睇 20 日，唔好只睇單日）。
6. **風險資產** — 美元、信貸、黃金、長債。
7. **個股樣本** — Stage 2 / Stage 4 名單，講有冇「領先股」走出嚟。
8. **與上次比較** — 咩改善、咩惡化（用 `data/` 快照 diff）。
9. **情境與行動** — 如果 A 發生就點做、如果 B 發生就點做；講風險，唔講目標價。

## 6. 寫作規範

- 用**香港廣東話**，但數字、術語保持專業（Stage 4、FTD、派貨日）。
- 每個判斷後面要有數據：❌「氣氛好差」→ ✅「SPY 9 個派貨日／25 日」。
- 講「如果…就…」，唔講「一定會」。唔好講「撈底」「必升」。
- 提到價位就同時寫日期：「11/20 低位 2,581.79」。
- 唔可以貼個人資料：冇 email、電話、本機路徑；只保留公開 GitHub 用戶名。
- 唔可以上載訪問逐字稿（版權）。只可以引用短句並註明出處。

## 7. 歷史政策

- `stan-weinstein-review-log.md` **只增不改**：新覆盤加喺最上面，舊節保留原文。
- 如果舊判斷要修訂，喺新一節寫「**修訂**：11/xx 講過 X，今日數據顯示 Y」，並保留舊節。
- `data/*.json` 係原始快照，**唔好手改**；改咗就冇得比較。
- 每份報告頂部要有「資料截止日」，底部要有免責聲明。

## 8. 常見問題

**Q：可唔可以加減觀察名單？**
改 `tools/marketdata.py` 嘅 `ETF` / `STOCKS`，然後喺覆盤記錄寫一句「樣本由 76 隻改為 N 隻」，因為廣度分母會變。

**Q：Nasdaq API 抓唔到？**
腳本會用 cache 舊數據並印 `FAIL`。見到 FAIL 就唔好出報告，等下一次或者手動檢查。

**Q：冇裝 matplotlib？**
`python3 tools/review.py --no-charts`，圖遲啲再補。

**Q：想加新指標？**
加喺 `tools/metrics.py`，同時更新本文第 4 節嘅門檻表，並喺下一次覆盤註明「新增指標」。
